# ShowUp reminder relay (optional)

A browser cannot wake a closed web app, so ShowUp can hand its upcoming reminder times to this small
server, which sends them to your phone through **ntfy**, **Telegram**, **email**, a **webhook** or
**Web Push** at the right moment. Zero dependencies, Node 20+, one JSON file for storage.

ShowUp works fine without it. You host it yourself; nothing is sent anywhere until you connect one in
Settings → "Optional: reminders when ShowUp is closed".

## Run

```sh
PORT=8787 RELAY_DATA=./data node server/relay.mjs
# or
docker build -f server/Dockerfile -t showup-relay . && docker run -p 8787:8787 -v relay-data:/data showup-relay
```

Put it behind HTTPS (Caddy, nginx, a platform's TLS). The app only talks to `https://` relays
(or `http://localhost`).

## Tell the app about it (build time)

The page's Content-Security-Policy only allows fetches to origins named when it is built:

```sh
SHOWUP_RELAY_ORIGINS="https://relay.example.org" npm run build
```

## Environment

| Variable | Default | Meaning |
| --- | --- | --- |
| `PORT` | 8787 | Listen port |
| `RELAY_DATA` | `./data` | Folder for `relay.json` (devices) and `vapid.json` (Web Push keys), mode 0600 |
| `RELAY_ALLOWED_ORIGINS` | `*` | Comma list of allowed browser origins (CORS) |
| `RELAY_MAX_DEVICES` | 1000 | Refuse new devices beyond this |
| `RELAY_RATE_PER_MIN` | 120 | Requests per IP per minute |
| `RELAY_TRUST_PROXY` | unset | `1` to read the client IP from `X-Forwarded-For` |
| `RELAY_CONTACT` | `mailto:admin@example.com` | VAPID contact; set to yours |
| `RELAY_EMAIL_API_KEY` / `RELAY_EMAIL_API_URL` / `RELAY_EMAIL_FROM` | unset | Enables email via a Resend-compatible HTTP API |

## API

`GET /healthz`, `GET /v1/info` (channels offered and the VAPID public key),
`PUT /v1/devices/:id` (channels plus the full list of upcoming reminders, replaces the previous list),
`POST /v1/devices/:id/test`, `DELETE /v1/devices/:id`. Every device route needs
`Authorization: Bearer <device secret>` (32+ characters, generated by the app; first use registers it).

## What it stores and trusts

* Per device: a hash of the secret, your channel settings (a Telegram bot token or webhook address is
  kept as plain text on the relay's disk), and `(time, title, text)` for upcoming reminders. With
  "Hide event titles" on, titles are replaced by "ShowUp reminder". Notes, links and other details are never sent.
* Devices unused for 90 days are deleted. Reminders more than 6 hours late are skipped.
* Outbound requests to webhook, ntfy server and push endpoints must be `https` and must resolve to public
  addresses (SSRF guard). Known limit: the check resolves DNS before `fetch` resolves it again, so a hostile
  DNS server could still rebind; run the relay without access to your internal network if that matters.
* Not verified here against real push services (FCM, Apple, Mozilla): the encryption matches the RFC 8291 test
  vector and decrypts in tests, but test with your own browser. On iPhone, Web Push only works for a
  Home-Screen-installed app (iOS 16.4+); ntfy or Telegram work without that.

## Tests

`npm run test:unit` covers the relay with a fake clock and a fake outbound `fetch`.
